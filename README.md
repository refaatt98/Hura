# Hura Business — Frontend

موقع تعريفي لـ Hura Business / Hura Projects: أفكار مشاريع جاهزة، مشاريع مخصصة، وورشات تدريبية.

## التشغيل

```bash
npm install
npm run dev
```

بعدها افتح الرابط اللي بيطلع (عادة http://localhost:5173).

| الأمر | الوظيفة |
|---|---|
| `npm run dev` | تشغيل نسخة التطوير |
| `npm run build` | فحص TypeScript وبناء نسخة الإنتاج بمجلد `dist` |
| `npm run preview` | معاينة نسخة الإنتاج محلياً |

## الستاك
React + TypeScript · Vite · Tailwind CSS v4 · React Router · motion · lucide-react

## هيكل المشروع
```
src/
  pages/        صفحة لكل ملف
  components/   مكوّنات مشتركة
  data/         محتوى ثابت (إنستغرام، معلومات الموقع) + نسخة البيانات الأولية
  lib/api.ts    كل جلب للبيانات بيمر من هون
  types.ts      أنواع البيانات
  index.css     الألوان والخطوط (tokens) بمكان واحد
```

- **تغيير الألوان والخطوط:** من `@theme` بأول `src/index.css`.
- **المحتوى:** كله بيتعدّل من `/admin` (مش من الكود).

## الصفحات
| الرابط | الصفحة |
|---|---|
| `/` | الرئيسية |
| `/ideas` · `/ideas/:id` | أفكار المشاريع وتفاصيل الفكرة (حاسبة + طلب شراء) |
| `/custom` | طلب مشروع مخصص (نموذج على خطوات) |
| `/workshops` · `/workshops/:id` | الورشات وتفاصيل الورشة (تسجيل) |

| `/admin` | لوحة الإدارة (بدون تسجيل دخول حالياً) |

## قاعدة البيانات (Supabase)
- الموقع مربوط بمشروع Supabase اسمه `hura`. كل القراءة والكتابة بتمر من `src/lib/api.ts`.
- الجداول: `site_settings`, `instagram_posts`, `ideas`, `workshops`, `idea_orders`, `custom_requests`, `workshop_registrations`, `contact_messages`, `admins`.
- **الملفات المرفوعة (صور وفيديو)** بتنحفظ على **Cloudflare R2** (bucket اسمه `hura`)، مش على Supabase:
  1. الموقع بيطلب رابط رفع مؤقت من Edge Function اسمها `r2-upload` (الكود بـ `supabase/functions/r2-upload`).
  2. الملف بينرفع مباشرة على R2، وبينحفظ رابطه العام (`pub-….r2.dev`).
  - مفاتيح R2 محفوظة بـ **Supabase Vault** (مش بالكود ولا بـ git)، وبس السيرفر بيقدر يقرأها.
  - الأنواع المسموحة: صور و فيديو (MP4/WEBM/MOV) لحد 500MB.
- ملفات قاعدة البيانات بـ `supabase/`: الجداول (`migrations/`) والبيانات الأولية (`seed.sql`).
- حجز الورشة بيمر من دالة `register_for_workshop` بتتأكد من المقاعد وبتحجز بخطوة وحدة.
- الرابط والمفتاح العام (publishable) موجودين بـ `src/lib/supabase.ts`. هاد آمن لأنهم أصلاً عامّين.
  **لا تحط أبداً service_role key أو توكن `sbp_...` بالكود.**

## لوحة الإدارة (`/admin`)
من لوحة الإدارة بتتحكم بكل المحتوى، وكل قسم بتبويب لحاله:
- **الطلبات:** طلبات الأفكار، المشاريع المخصصة، تسجيلات الورشات، الرسائل.
- **المحتوى:** الأفكار، الورشات، منشورات إنستغرام (مع رفع صور).
- **الإعدادات:** القسم الأول بالرئيسية، معلومات التواصل، الأسئلة الشائعة، نموذج المشروع المخصص.
- **نصوص الموقع:** كل نص بالموقع (عناوين، أزرار، خانات، رسائل) مقسّم حسب الصفحة.

النصوص الأصلية موجودة بـ `src/data/texts.ts`؛ أي تعديل من اللوحة بينحفظ بـ `site_settings.texts` وبيغطي على الأصلي، وفي زر «رجّع الأصلي» لكل نص.

⚠️ **حالياً بدون تسجيل دخول، بطلب صاحب المشروع.** أي حدا بيعرف الرابط بيقدر يشوف الطلبات (أسماء وأرقام) ويعدّل ويحذف.
لإرجاع الحماية: شغّل `supabase/restore_admin_protection.sql` وارجع شاشة تسجيل الدخول (Supabase Auth). الإيميلات المسموحة بجدول `admins`.

## النشر على Netlify
الإعدادات جاهزة بـ `netlify.toml` (أمر البناء، مجلد `dist`، وتوجيه كل الروابط لـ `index.html` عشان React Router).
اربط الـ repo من Netlify ← Add new site ← Import from Git، وما في داعي تغيّر إشي.
الموقع مسموح يظهر جوا `<iframe>` بأي موقع (header: `frame-ancestors *`).
